# (アイン、ソフ、オウル)

**Three.js のための数学と実装** — 数学の予備知識ゼロから、作品を人に見せられる形にするところまで。全182章の学習サイトです。

Three.js は箱を 1 つ出すところまでは簡単ですが、その先でベクトル・回転・行列・投影の壁にぶつかります。
このサイトは、その壁をこえるために必要な数学**だけ**を、
3D に固有でない土台（第1部）と 3D の数学（第2部）の 2 段で身につけ、
それを実際の Three.js のコードにし（第3部）、
作品を 2 つ最初から最後まで組み上げ（第4部）、
それを人に見せられる形に仕上げます（第5部）。

- 公式の暗記は求めません。スライダーを動かして 3D が変わるのを見ながら理解します
- 各章は「Three.js で何ができなくて困るか → 直感 → 図とデモ → はじめて数式 → 実際のコード」の順です
- **数式には必ず「日本語で言うと」と「実際に計算してみる」を併記しています。**
  意味が分かることと自分で回せることは別なので、全188個の数式に実数値での手順を添えました
- **第3部より後のコードは、ページの中で書き換えて実行できます**
- **画像もモデルも 1 つも使いません。**リポジトリにバイナリはありません

## 詰まらないための作り

独学が止まるのは知識が足りないときではなく、**次の一手が決まらないとき**です。
そこで情報を増やすのではなく、判断を減らす方向で 3 つだけ手当てしています。

- **ホームには「続きから」が 1 枚だけ出ます。** 進捗から一意に決まり、選択肢は並べません
  （読んでいない最初の章 → 残りの演習 → 公開、の順に送ります）
- **全章の冒頭に戻り先があります。** 第3部より後は「この章で使う数学」、
  土台の 2 部は `requires` から「この章の前に読んでおく章」を出します
- **クイズを間違えたときだけ、前提の章へのリンクが出ます。** 正解した人には出しません

各部の見出しには「ここまでで何が作れるようになるか」を 1 行添えています。
章末の API チップは threejs.org の該当ページへのリンクになっています。

## 動かす

Node.js 22 以上が必要です。

```bash
npm install
npm run dev        # 開発サーバ（http://localhost:5173/webgl_manabe/）
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバ |
| `npm run build` | 型チェック＋本番ビルド（`dist/`） |
| `npm run preview` | ビルド結果をローカルで配信 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run check` | コンテンツの整合性チェック（デモ id・用語・章リンク・クイズ・計算例・演習・逆引き） |
| `npm run smoke` | Playwright で全ルートを実際に開いて検証（要 `npm run build`）。`-- --part=basics` で部を絞れる |

`npm run smoke` は、全182章を同じタブで連続して開き、次を確認します。

- console error / pageerror が 1 件も出ないこと
- 各章のデモのキャンバスが実際に生成されていること
- **各サンドボックスが自動実行され、iframe の中にキャンバスを作ること**
- 182章を渡り歩いても WebGL コンテキストが枯渇しないこと（＝破棄漏れがないこと）
- ダーク／ライト両テーマで、本文 7:1・補助テキスト 4.5:1 のコントラスト比を満たすこと
- **すべての数式に計算例が描画されていること**
- **演習ページに全546問が出て、通しで解けて、「解いた」印がリロード後も残ること**
- ホームの「続きから」が 1 枚だけ出ていること
- 動きを減らす設定でも壊れないこと、狭い画面で横にはみ出さないこと

スクリーンショットは `artifacts/` に出力されます（Git 管理外）。

この 4 つ（`typecheck` → `check` → `build` → `smoke`）は、pull request と `main` への push で
GitHub Actions でも走ります（`.github/workflows/ci.yml`）。
**smoke だけは部ごとに分けて並列に**回しています ― 章が増えるほど直線的に伸びるためです。
3D は SwiftShader のソフトウェア描画で動かしています。失敗したときだけ、
スクリーンショットが実行結果の artifact として残ります。

## 作りの要点

コードを読むときの地図です。

- **章はデータ**（`src/content/chapters/*.ts`）。本文・数式・デモ・クイズを 1 つのオブジェクトに書き、
  共通のレンダラ（`src/app/pages/chapter.ts`）が描画します。目次・検索索引・前提知識マップ・用語リンクも、
  すべてこの同じデータから導かれます。
- **3D は Stage に集約**（`src/three/stage.ts`）。レンダラ・カメラ・操作・リサイズ・破棄をここで一手に持ちます。
  SPA で章を行き来するため、破棄漏れは即座に致命傷（ブラウザが同時に持てる WebGL コンテキストは 8〜16 程度）になるので、
  画面外では描画を止め、ページ離脱時にすべて解放します。
- **デモの UI も仕様から生成**（`src/ui/controls.ts`）。各デモは three のロジックだけを書きます。
- **ベクトルの色は全章で固定**（`src/styles/base.css` の `--vec-*`）。シアン＝入力 a、ピンク＝入力 b、
  アンバー＝計算結果、白＝法線／光、破線の灰＝補助線。赤緑の組を避け、ラベルと線種でも区別できるようにしています。
- **ネオンは線にだけ乗せる。** 本文にグローやグラデーションはかけず、コントラスト比を実測で担保しています。
- **サンドボックス**（`src/sandbox/`, `src/ui/sandbox.ts`）。第3部より後のコードは iframe の中で実行します。
  three をもう一部バンドルすると 570KB 増えるので、**親ページが読み込んでいる three の名前空間を列挙し、
  それを再エクスポートするだけの小さな Blob モジュール**を作り、インポートマップで `three` に対応づけています。
  おかげで iframe の中でも `import * as THREE from 'three'` がそのまま書け、
  **教材のコードと実際に走るコードが完全に同じ形**になります。バンドルは 1 バイトも増えません。
  読み込むのは**そのコードが実際に `import` しているものだけ**なので、ブルームを使わない章の読者に
  postprocessing のコードが降ってくることはありません。
  利用者のコードは独立した Blob モジュールとして読み込むので、エラーの行番号がエディタの行番号と一致します。
  エディタは透明な `textarea` を色付きの `<pre>` に重ねる方式で、既存の `highlight()` を再利用しています
  （新しい依存はありません）。
- **コードの地図**（`scanSections()`）。長いサンドボックスの上に、区切りコメント
  （`/* ---- 星空 ---- */`）を**実行時に走査して**並べます。押すとその位置へ飛び、右の数字は行数です。
  **地図に行番号は書きません** ― コードを 1 行足しただけで古くなるからです。見出し名だけを持ち、
  位置は毎回数え直します。`guide.focus` に**見出し名**を並べるとそこだけ強調され、
  「この章で新しいのはこの 52 行だけ」が一目で分かります。
  見出しの文言を直したときに `guide` が取り残されないよう、**`npm run check` が実在を検査します**。

  three は親ページ側で動くため、iframe で作った `Float32Array` は realm が違い、three の `instanceof`
  判定を通りません。そこで iframe の型付き配列コンストラクタを親のものに向けています
  （`src/sandbox/runtime.ts`）。

- **素材はすべてコードで作る**（第4部）。惑星の地表・雲・街明かりは 3 次元ノイズから、
  街は決め打ちの乱数と再帰的な分割から生成しています。画像を用意しないので、
  「なぜこの見た目なのか」が全部コードに書いてあり、数値を変えれば別のものが出ます。
  球にテクスチャを貼るときは **UV ではなく方向ベクトルでノイズを引く**（`src/three/noise.ts`）。
  こうすると経度 0 度の継ぎ目と極の歪みが原理的に発生しません。

依存は three / KaTeX / フォント（@fontsource）だけです。Markdown パーサ・シンタックスハイライタ・
検索ライブラリ・グラフ描画ライブラリ・ノイズライブラリはいずれも入れず、必要な範囲だけ自前で書いています。

## 公開

`main` に push すると GitHub Actions が `dist/` を GitHub Pages へデプロイします
（`.github/workflows/deploy.yml`）。

初回のみ、リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。

配信先が `https://<user>.github.io/webgl_manabe/` である前提で、`vite.config.ts` の `base` を
`/webgl_manabe/` に固定しています。別のパスで配信する場合はここを変えてください。
